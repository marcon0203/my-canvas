# 功能走查（产品视角）

走查方式：真实浏览器跑完整条主流程（一句话 → 大纲 → 剧本 → 资产 → 分镜 → 关键帧 →
批量转视频 → 自动成片 → 导出），再逐个入口点进去看。下面每条都标了复现路径和代码位置。

**格式**：User Story ｜ **故事总数**：14 ｜ **预估**：5 个 P0 约 2 个迭代，其余 1 个迭代

一句话结论：**流程是通的，但流程后半段（转视频 → 成片 → 数据）是演出来的。**
前半段（大纲/剧本/资产/分镜）已经接了真模型，后半段还是 `setTimeout` + 改状态位，
却照样扣积分、照样弹「消耗 24 积分」。一个用户跑完整条流程，拿不到 mp4，
数据页还会告诉他命中率 0%。这是目前最伤信任的地方。

## 故事列表

### 故事 1：批量转视频要真的调模型

**作为一个用户，我点「一键批量生成视频」并被扣了 24 积分之后，我想要真的得到视频文件，
以便于我后面能剪出片子。**

现状：`src/store/project.ts:242` `batchVidStart()` 只做三件事 —— `vid='run'`、
`takes += 4`、`credits -= 24`；1500ms 后 `batchVidDone()` 把 `vid='ok'`、`key=true`。
全程没有任何请求、没有任何文件。`src/features/storyboard/StoryboardPage.tsx:105` 和
`src/store/agent.ts:389` 两处入口都是这套。
讽刺的是 `src/domain/agent/tasks.ts:133` 自己写着 `by: 'local'`、
「排期本地算，真跑要接上视频模型」—— 任务分工表是诚实的，主流程的 toast 不诚实。

验收标准：
- [ ] 点击后逐镜发起真实视频生成请求，失败的镜头标 `fail` 并显示原因，不是全部变 `ok`
- [ ] 产出文件落到项目目录，`shotFiles` 补丁把 `file` 写进 shot（复用 `media::fetch_all` 那条链路）
- [ ] 只有真正拿到文件的镜头才扣积分；一个都没成时不扣
- [ ] 没配置视频模型时按钮禁用并说明原因，而不是先扣分再假装成功
- [ ] `tasks.ts` 里该任务从 `by:'local'` 改成 `by:'model'`，两张表对得上

优先级：P0 ｜ 工作量：L ｜ 依赖：无（`media::fetch` / `film.render` 已就位）

### 故事 2：采纳一步后不要立刻推进到下一步

**作为一个用户，我采纳了「批量转视频」之后，我想要系统等它真的跑完再往下走，
以便于自动成片不会因为素材还没好而失败。**

现状：`src/store/agent.ts:389` 采纳后同步 `batchVidStart()` 就返回，队列立刻推进到
下一步「自动成片」，而 `planAutocut` 取的是 `c.shots.filter(s => s.vid === 'ok')`，
此刻全是 `run`，于是必然拿到空集。

浏览器实测：
```
第 6 次采纳 | 步骤 6/7 | 批量转视频 · 18 镜
第 7 轮：等了 15 秒没有采纳按钮
  面板尾：「还没有可用的视频片段。先批量转视频，再逐镜判定。」
```
手动等 3 秒再重新发起自动成片 → 「取 18 段可用素材…自动成片 · 18 段 / 60s」成功。
也就是说这不是缺功能，是**每个走主流程的用户都会踩的确定性竞态**。

验收标准：
- [ ] 异步动作（转视频等）完成后才推进队列，中间步骤显示进行中而不是直接跳过
- [ ] 上一步失败时队列停住并说明，不再盲目执行依赖它的下一步
- [ ] 自动成片在素材为空时给的提示要指向真实原因（上一步还在跑／上一步失败），不是「先批量转视频」
- [ ] 补一条回归测试：连跑 7 步不出现「还没有可用的视频片段」

优先级：P0 ｜ 工作量：M ｜ 依赖：故事 1（真跑之后才有真的完成信号）

### 故事 3：数据页和剪辑页不能互相打脸

**作为一个用户，我想要各个页面对「有多少可用镜头」说法一致，
以便于我知道该信哪个。**

现状：同一时刻，数据页显示「可用镜头 0 ／ 命中率 0% ／ 单条可用成本 —」，
剪辑页显示「18 段可用 · 60s」。原因：数据页 `usableShots` 和
`MetricsPage.tsx:23` 数的是 `verdict === 'ok'`，剪辑页数的是 `vid === 'ok'`，
而 `batchVidDone()` 从不设置 `verdict`。

验收标准：
- [ ] 「可用」只有一个定义，写在一处，所有页面调用同一个函数
- [ ] 若保留「生成成功」与「人工判定可用」两个概念，两页分别显示两个数字并各自标清楚
- [ ] 数据页在还没有任何人工判定时，显示「待判定 18」而不是「命中率 0%」
- [ ] 加测试断言两页读的是同一个 selector

优先级：P0 ｜ 工作量：S ｜ 依赖：无

### 故事 4：模型没真正产出时不要拿模板冒充

**作为一个用户，我输入两个完全不同的需求，我想要得到两份不同的大纲，
以便于我知道模型真的读了我的输入。**

现状：两次完全不同的输入产出了**一字不差**的同一份六场大纲
（「建立日常，埋下第一个异样」…），而且外面包着流式动画、步骤卡、「消耗 2 积分」，
看起来和真跑一模一样。这是模板兜底被当成模型输出渲染了。

验收标准：
- [ ] 走了兜底模板时，卡片明确标注「示例大纲（未调用模型）」并且不扣积分
- [ ] 未配置模型／调用失败时给出可操作的错误（去哪配、报什么错），不静默降级
- [ ] 兜底内容不参与流式打字动画，视觉上要能一眼区分
- [ ] 加测试：同一 store 两次不同输入若产出完全相同文本则失败

优先级：P0 ｜ 工作量：M ｜ 依赖：无

### 故事 5：剧本要把每一场都写完

**作为一个用户，我点「写剧本」，我想要六场都写出来，
以便于我不用手动补另外五场。**

现状：`script.draft` 只写了「場景1」，然后流程就推进到下一步，剩下 5 场是空的。
后面的资产提取、分镜都建立在这 1/6 的内容上。

验收标准：
- [ ] 一次「写剧本」覆盖当前幕下所有场次，逐场显示进度
- [ ] 每场失败可单独重试，不牵连已写好的场
- [ ] 仍有场次为空时不允许静默进入下一步，给出「还有 5 场没写」的拦截
- [ ] 按场次数量计费，而不是按一次调用

优先级：P0 ｜ 工作量：M ｜ 依赖：无

### 故事 6：资产提取要挡住占位符

**作为一个用户，我想要资产列表里只有真实的角色/场景/道具，
以便于我不用手动删掉一堆垃圾条目。**

现状：模板剧本里的 `待定场景 · 待定时间` 这一行被原样提取成了两个资产：
「待定场景」和「待定时间」，分组 `场景 · SCENE-001`。输入是垃圾，输出照单全收。

验收标准：
- [ ] 占位类词（待定/TBD/未命名/空）不进入资产列表
- [ ] 源剧本为空或仅含占位内容时，直接提示「剧本还没写，先写剧本」而不是提取出空壳资产
- [ ] 重复名称的资产合并而不是并列
- [ ] 加测试：喂入模板占位剧本，断言提取结果为空

优先级：P1 ｜ 工作量：S ｜ 依赖：故事 5

### 故事 7：工作空间目录说明要包含 providers/

**作为一个用户，我想要在设置里看到我的 api key 存在哪个文件，
以便于我能自己备份、检查、或者手动改。**

现状：`src-tauri/doc/src/workspace.rs:25` 的 `SUBDIRS` 有三项
（skills / providers / projects），但 `src/api/desktop.ts:385` 的浏览器兜底列表

结果：用户在设置里根本看不到 api key 存在哪。这正是仓库 README 自己批评过的

- [ ] 目录说明只有一个来源；前端兜底不再硬编码第二份列表
- [ ] 设置页能看到 `providers/`，说明里写明「api key 也在里面，文件权限 0600」
- [ ] 桌面端额外显示已有几个供应商文件
- [ ] 加测试：Rust `SUBDIRS` 与前端展示项数量一致

优先级：P1 ｜ 工作量：S ｜ 依赖：无

### 故事 9：项目 id 不要直接用中文句子

**作为一个用户，我想要项目在磁盘和 URL 里有个稳定的短 id，
以便于改名或用特殊字符时不出问题。**

现状：项目 id 是「用户那句话 + 日期」，既做 URL 又做磁盘目录名：
`/project/%E4%B8%80%E4%B8%AA%E4%BF%AE...-20260918/outline`。

验收标准：

- [ ] 改标题不影响磁盘目录和已有链接
- [ ] 同一天同一句话创建两次能共存
- [ ] 已有项目有迁移路径，不丢数据

### 故事 14：积分要和真实成本挂钩

**作为一个用户，我想要「消耗 2 积分」对应真实的 token/调用成本，

## 故事地图

**必须做（先修可信度）**：4 兜底冒充 → 1 批量转视频真跑 → 2 队列竞态 → 5 剧本写全 → 3 口径统一

这五条是一条线：现在用户跑完主流程拿不到 mp4，
而界面从头到尾都在表现得像拿到了。先让「做了就是做了、没做就说没做」成立。

**应该做（可用性）**：7 providers 目录 → 6 占位符 → 10 自定义供应商 → 8 首页 → 9 项目 id

**有余力再做**：11 排序说明 → 12 判定引导 → 13 资源管理 → 14 真实计费

## 技术备注

- **两个事实来源反复出现**：`SUBDIRS`（Rust/TS 各一份）、「可用」的两种判定
  （`verdict` / `vid`）、`tasks.ts` 的 `by` 与实际实现。
  `tasks.test.ts` 里那条「两张表对得上」的测试已经抓住过一次，值得把这个模式推广到
  目录表和可用口径上。
- **采纳队列需要异步化**：`applyProposal` 现在是同步函数，`setTimeout` 是它唯一的
  「异步」。故事 1 和 2 实际上是同一次改造 —— 队列要能等一个真实的 pending 状态。
- **前半段已经接了真模型**（`agent/src/{script,assets,shots}.rs` + `media::fetch_all`
  + `doc/src/render.rs` 的 ffmpeg 链路），故事 1 是把后半段接到已有链路上，
  不是从零开始。
