> 本地模板自产占位符喂给下一步），一并修了，记在文末「收尾复验」。

走查方式：真实浏览器跑完整条主流程（一句话 → 大纲 → 剧本 → 资产 → 分镜 → 关键帧 →
批量转视频 → 自动成片 → 导出），再逐个入口点进去看。下面每条都标了复现路径和代码位置。

**格式**：User Story ｜ **故事总数**：14 ｜ **预估**：5 个 P0 约 2 个迭代，其余 1 个迭代

一句话结论：**流程是通的，但流程后半段（转视频 → 成片 → 数据）是演出来的。**
前半段（大纲/剧本/资产/分镜）已经接了真模型，后半段还是 `setTimeout` + 改状态位，
却照样扣积分、照样弹「消耗 24 积分」。一个用户跑完整条流程，拿不到 mp4，
数据页还会告诉他命中率 0%。这是目前最伤信任的地方。

### 故事 1：批量转视频要真的调模型

**作为一个用户，我点「一键批量生成视频」并被扣了 24 积分之后，我想要真的得到视频文件，
以便于我后面能剪出片子。**

现状：`src/store/project.ts:242` `batchVidStart()` 只做三件事 —— `vid='run'`、
`takes += 4`、`credits -= 24`；1500ms 后 `batchVidDone()` 把 `vid='ok'`、`key=true`。
全程没有任何请求、没有任何文件。`src/features/storyboard/StoryboardPage.tsx:105` 和
`src/store/agent.ts:389` 两处入口都是这套。
讽刺的是 `src/domain/agent/tasks.ts:133` 自己写着 `by: 'local'`、
「排期本地算，真跑要接上视频模型」—— 任务分工表是诚实的，主流程的 toast 不诚实。

验收标准：
- [ ] 点击后逐镜发起真实视频生成请求，失败的镜头标 `fail` 并显示原因，不是全部变 `ok`
- [ ] 产出文件落到项目目录，`shotFiles` 补丁把 `file` 写进 shot（复用 `media::fetch_all` 那条链路）
- [ ] 只有真正拿到文件的镜头才扣积分；一个都没成时不扣
- [ ] 没配置视频模型时按钮禁用并说明原因，而不是先扣分再假装成功
- [ ] `tasks.ts` 里该任务从 `by:'local'` 改成 `by:'model'`，两张表对得上

**做法**：新增 `runVideoBatchOnDesktop`，逐镜调 `video.generate`，落盘后交一份
`shotFiles` 补丁。失败的镜头也写回项目（takes 加一、原因留着、状态回待转），
只对真拿到文件的那几镜计费。`tasks.ts` 新增 `by:'tool'` 一档 —— 真跑真花钱，
但不是让模型写文字而是一个循环，所以它没有也不该有 SKILL.md。
分镜页那个按钮改走 Agent，不再自己改 store。

优先级：P0 ｜ 工作量：L ｜ 依赖：无 ｜ **已完成**

### 故事 2：采纳一步后不要立刻推进到下一步

**作为一个用户，我采纳了「批量转视频」之后，我想要系统等它真的跑完再往下走，
以便于自动成片不会因为素材还没好而失败。**

现状：`src/store/agent.ts:389` 采纳后同步 `batchVidStart()` 就返回，队列立刻推进到
下一步「自动成片」，而 `planAutocut` 取的是 `c.shots.filter(s => s.vid === 'ok')`，
此刻全是 `run`，于是必然拿到空集。

浏览器实测：
```
第 6 次采纳 | 步骤 6/7 | 批量转视频 · 18 镜
第 7 轮：等了 15 秒没有采纳按钮
  面板尾：「还没有可用的视频片段。先批量转视频，再逐镜判定。」
```
手动等 3 秒再重新发起自动成片 → 「取 18 段可用素材…自动成片 · 18 段 / 60s」成功。
也就是说这不是缺功能，是**每个走主流程的用户都会踩的确定性竞态**。

验收标准：
- [ ] 异步动作（转视频等）完成后才推进队列，中间步骤显示进行中而不是直接跳过
- [ ] 上一步失败时队列停住并说明，不再盲目执行依赖它的下一步
- [ ] 自动成片在素材为空时给的提示要指向真实原因（上一步还在跑／上一步失败），不是「先批量转视频」
- [ ] 补一条回归测试：连跑 7 步不出现「还没有可用的视频片段」

**做法**：没有按「等异步完成再推进」去做，而是把活儿挪到产物**之前** ——
生成在这一轮里跑完，产物是一份已落盘的文件清单，采纳同步写完，竞态不存在了。
`applyProposal` 里那个 `setTimeout` 删掉。`agent.race.test.ts` 复现走查现场：
采纳后不等任何定时器，紧接着算自动成片就能看到这些片段。

顺带发现自动成片本身也是空的（产物是 `{t:'run'}`，采纳只弹一句话），
现在产出真的时间线 —— 新增 `planTimeline`，与 Rust 的 `timeline::plan` 对着
同一份夹具做 parity。`ProposalPatch` 里的 `run` 这一档整个删掉了。

优先级：P0 ｜ 工作量：M ｜ 依赖：无 ｜ **已完成**

### 故事 3：数据页和剪辑页不能互相打脸

**作为一个用户，我想要各个页面对「有多少可用镜头」说法一致，
以便于我知道该信哪个。**

现状：同一时刻，数据页显示「可用镜头 0 ／ 命中率 0% ／ 单条可用成本 —」，
剪辑页显示「18 段可用 · 60s」。原因：数据页 `usableShots` 和
`MetricsPage.tsx:23` 数的是 `verdict === 'ok'`，剪辑页数的是 `vid === 'ok'`，
而 `batchVidDone()` 从不设置 `verdict`。

验收标准：
- [ ] 「可用」只有一个定义，写在一处，所有页面调用同一个函数
- [ ] 若保留「生成成功」与「人工判定可用」两个概念，两页分别显示两个数字并各自标清楚
- [ ] 数据页在还没有任何人工判定时，显示「待判定 18」而不是「命中率 0%」
- [ ] 加测试断言两页读的是同一个 selector

**做法**：新增 `domain/shots/usable.ts` 作为唯一词表 —— `hasClip`（出过片）/
`awaitingCall`（出过片没判定）/ `cutReady`（能入片）/ `usable`（人判定可用）。
保留了两个概念而不是合并成一个：出片和认可确实是两件事，界面措辞区分成
「判定可用」「可入片」「待判定」「未出片」。`usable.guard.test.ts` 扫源码，
谁再在页面里手写这两个 filter 就点名（反向验证过会失败）。

优先级：P0 ｜ 工作量：S ｜ 依赖：无 ｜ **已完成**

### 故事 4：模型没真正产出时不要拿模板冒充

**作为一个用户，我输入两个完全不同的需求，我想要得到两份不同的大纲，
以便于我知道模型真的读了我的输入。**

现状：两次完全不同的输入产出了**一字不差**的同一份六场大纲
（「建立日常，埋下第一个异样」…），而且外面包着流式动画、步骤卡、「消耗 2 积分」，
看起来和真跑一模一样。这是模板兜底被当成模型输出渲染了。

验收标准：
- [ ] 走了兜底模板时，卡片明确标注「示例大纲（未调用模型）」并且不扣积分
- [ ] 未配置模型／调用失败时给出可操作的错误（去哪配、报什么错），不静默降级
- [ ] 兜底内容不参与流式打字动画，视觉上要能一眼区分
- [ ] 加测试：同一 store 两次不同输入若产出完全相同文本则失败

**做法**：凡是已接模型的活却落到本地 `plan()`，一律标 `demo` —— 卡上写
「示例 · 未调用模型」、不扣积分、不走打字动画、步骤卡一并去掉（那几张卡的
意思是「正在干这几件事」）。桌面端落到这儿不是「示例」而是配置问题，
正文换成去哪配、缺什么。

优先级：P0 ｜ 工作量：M ｜ 依赖：无 ｜ **已完成**

### 故事 5：剧本要把每一场都写完

**作为一个用户，我点「写剧本」，我想要六场都写出来，
以便于我不用手动补另外五场。**

现状：`script.draft` 只写了「場景1」，然后流程就推进到下一步，剩下 5 场是空的。
后面的资产提取、分镜都建立在这 1/6 的内容上。

验收标准：
- [ ] 一次「写剧本」覆盖当前幕下所有场次，逐场显示进度
- [ ] 每场失败可单独重试，不牵连已写好的场
- [ ] 仍有场次为空时不允许静默进入下一步，给出「还有 5 场没写」的拦截
- [ ] 按场次数量计费，而不是按一次调用

**做法**：`runScriptOnDesktop` 遍历所有缺正文的场次，一场一次请求（写崩了
只重那一场，且后一场要读前一场的结尾，本来就得串着来）。第二场接的是刚写完的
第一场 —— `scriptInput` 收一份 `fresh` 映射，因为产物还没采纳，项目里还没有它。
六场汇总成一份产物，按场次数计费。单场失败点名列在卡上。
提取资产 / 拆镜头那两轮开头，如果还有场次空着就说出来。

事件泵顺带拆成 `pumpRaw` + `pump`：原来一份草稿就弹一张卡，跑多轮汇总需要
更底层的入口。

优先级：P0 ｜ 工作量：M ｜ 依赖：无 ｜ **已完成**

### 故事 8：首页三张模式卡要么能用要么别放

**作为一个用户，我点首页的卡片，我想要它带我去做点什么，
以便于我不会以为产品坏了。**

### 故事 9：项目 id 不要直接用中文句子

**作为一个用户，我想要项目在磁盘和 URL 里有个稳定的短 id，
以便于改名或用特殊字符时不出问题。**

现状：项目 id 是「用户那句话 + 日期」，既做 URL 又做磁盘目录名：
`/project/%E4%B8%80%E4%B8%AA%E4%BF%AE...-20260918/outline`。
一句话很长，URL 不可读，改标题会不会换目录也不清楚。

验收标准：
- [ ] id 与标题分离，id 短、稳定、URL 安全
- [ ] 改标题不影响磁盘目录和已有链接
- [ ] 同一天同一句话创建两次能共存
- [ ] 已有项目有迁移路径，不丢数据

**做法**：**改小了范围**。「改标题不动 id」这条原来就成立（只是没测试守着），
所以没做迁移；id 里那截名字从 14 字收到 8 字。
「目录名可读」和「URL 短」本来就冲突（中文一个字编码成九个字符），
这里选的是目录名可读 —— 用户会去 `projects/` 里翻，URL 没人手打。
测试里只卡字数，不承诺 URL 长度。

优先级：P1 ｜ 工作量：S（原估 M）｜ 依赖：无 ｜ **已完成**

### 故事 12：没有人工判定时给出引导

### 故事 13：资源管理入口的处理

**作为一个用户，我点进资源管理看到「还没实现，先占个入口」，
我想要要么能用要么别出现在一级菜单，以便于导航里没有死路。**

验收标准：
- [ ] 未实现的一级入口统一处理（隐藏或灰显+说明预计做什么）
- [ ] 占位文案说明这里将来放什么，而不只是「没实现」

**做法**：`ResourcesRoute` 写清「将来管什么、现在那些东西在哪」；
左栏「还没做」的入口压低视觉权重并在 title 里说明。

优先级：P2 ｜ 工作量：S ｜ 依赖：无 ｜ **已完成**

### 故事 14：积分要和真实成本挂钩

**作为一个用户，我想要「消耗 2 积分」对应真实的 token/调用成本，
以便于我能判断这条片子值不值。**

现状：积分是本地一个数字，随手扣（大纲 2、关键帧 10、转视频 24），
和真实调用量无关；数据页的「单条可用成本」因此也没有意义。

验收标准：
- [ ] 真实调用后按实际用量记账，本地常量只作为预估显示
- [ ] 预估与实际都能看到
- [ ] 本地/模板步骤不记账

**做法**：rig 的 `PromptResponse.usage` 里就有厂商报的真实 token，
在我们已经拿 `r.output` 的那一行旁边。`structured::Out` 加一个 usage 出口，
`run.rs` 转成 `RunEvent::Usage` 发上来，跟着项目落盘。

**没有把 token 换算成积分** —— 那需要各家的价格表，编一个汇率只是换个地方
造假数据。积分明确留作预估，数据页把「预估消耗 / 实际用量 / 进出比」并排摆着，
并写明前者与厂商计费无关。全 0 是 rig 约定的「那家没报」，单独记成
`unreported`，否则 token 偏低看起来像很省。

用量在**请求发出的那一刻**就记，不等采纳 —— token 烧掉了，丢弃也退不回来；
积分仍是采纳时才扣（那表达的是「你打算为这份产物付多少」）。

优先级：P2 ｜ 工作量：L ｜ 依赖：无 ｜ **已完成（口径调整）**
