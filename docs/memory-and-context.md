# 记忆与上下文：照 Claude Code 抄作业

> 状态：**方案，还没实现**。写这份是因为「记忆」这件事一旦落错了地方（比如塞进
> 项目文件、或者堆成一大坨每次全带），后面改的代价很大。
>
> 相关：[桌面端架构](./desktop-architecture.md) · [Rust 侧说明](../src-tauri/README.md)

## 0. 为什么现在要做这个

现在的真实状态（我查过代码，不是印象）：

| 层 | 存在哪儿 | 跟着项目走吗 |
|---|---|---|
| 项目内容 | `<workspace>/projects/<id>/`（outline.md、script/*.md、assets.json…） | ✅ |
| 会话记录 | 浏览器 localStorage（`studio.chat.live.<id>` / `.archive.<id>`） | ❌ 换机器看不到 |
| **模型的记忆** | **没有** | — |

第三层是空的：`structured.rs` 里是 `stream_prompt(prompt)`，**没有 `.history()`**。
模型每次看到的只有人格提示词、这轮展开的 skill 正文、以及那条链路自己组装的
结构化输入 —— 而输入里的 `idea` 只有**当前这一句**。

后果很具体：你说「起草大纲」，再说「再短一点」，模型不知道「再短一点」在说什么。
**界面上有对话历史，模型看不到它。**

有一个补偿设计，是刻意的：每条链路都把项目现状组装进输入（写剧本送前一场结尾、
拆镜头送正文 + 定稿资产）。所以上下文是**从磁盘重建的**，不是从对话里来的。
这比堆对话历史可靠，但它答不了两类需求：

- 「接着上一句说」——一轮之内的追问
- 「我不要旁白」「这片子的调性是冷的」——跨会话的设定

这份方案解决后者，顺带给前者划一条边界。

## 1. Claude Code 实际是怎么做的

查的是 [官方文档](https://code.claude.com/docs/en/memory) 与
[上下文窗口](https://code.claude.com/docs/en/context-window)，不是凭印象。

### 1.1 两套记忆，分工明确

|  | CLAUDE.md | Auto memory |
|---|---|---|
| 谁写 | 人 | Claude 自己 |
| 内容 | 指令、规则 | 学到的东西、你给的纠正 |
| 作用域 | 组织 / 用户 / 项目 | 每个 repo 一份（worktree 共享） |
| 加载 | 每次会话全量（≤4 MiB，建议 <200 行） | 每次会话加载 `MEMORY.md` 的**前 200 行或 25 KB** |

### 1.2 层级：拼接，不覆盖

```
/etc/claude-code/CLAUDE.md      组织策略（不可排除）
~/.claude/CLAUDE.md             我的偏好，所有项目
./CLAUDE.md 或 ./.claude/CLAUDE.md   项目，进版本库
./CLAUDE.local.md               我在这个项目的私货，gitignore
```

**从文件系统根往下拼，越近的越后读。** 同一目录里 `CLAUDE.local.md` 排在
`CLAUDE.md` 之后。所以「越具体的越靠后」，冲突时后面那份说话更响。

cwd **之上**的启动时全加载；cwd **之下**子目录里的，等 Claude 读到那个目录里的
文件时才加载。

### 1.3 `@import`

CLAUDE.md 里 `@path/to/file` 会被展开并在启动时一起进上下文，最多 **4 跳**，
相对路径相对**文件自身**解析。反引号里的 `` `@README` `` 不当导入。

注意：导入**不省上下文**，只是拆文件方便维护 —— 文档里明确说了这一点。

### 1.4 `.claude/rules/` 与 `paths:` —— 省上下文的核心

```markdown
---
paths:
  - "src/api/**/*.ts"
---
# API 开发规则
- 所有端点必须做入参校验
```

没有 `paths` 的 rules 启动时就加载；**有 `paths` 的只在 Claude 读到匹配的文件时
才进上下文**。这是「规则很多但上下文有限」的解法。

### 1.5 Auto memory 的结构：索引 + topic

```
~/.claude/projects/<project>/memory/
├── MEMORY.md            索引，一条一行，每次会话加载（前 200 行 / 25KB）
├── user_role.md         一条记忆
├── feedback_testing.md
└── ...                  topic 文件，启动时不加载，按需读
```

四类 `type`：`user`（角色与偏好）/ `feedback`（你给的纠正）/ `project`（正在做的事、
决定）/ `reference`（外部信息在哪儿）。

几条关键约束，都值得抄：

1. **明确跳过能从代码推出来的东西**（架构、文件路径、修 bug 的办法），
   也跳过 CLAUDE.md 已经说过的
2. **不是每次会话都记**。Claude 自己判断这条以后有没有用
3. **写完量一次**：接近 200 行 / 25KB 就提醒缩短（一条一行、细节挪进 topic、
   合并或删掉过期的）；**超了写入仍然成功，但返回一个错误让 Claude 重写索引**——
   因为超出部分下次加载会被静默丢掉
4. **`modified` 时间戳**（ISO 8601），让人和模型都知道这条事实有多新
5. 机器本地，不跨机器同步。会话记录到期清理时**跳过 memory 目录**

### 1.6 压缩是两级，不是一步

> "It clears older tool outputs first, then summarizes the conversation if needed."

先清老的工具输出，不够才总结对话。压缩后**从磁盘重新注入**：

| 机制 | 压缩后 |
|---|---|
| 系统提示词、output style | 仍然生效 |
| 项目根 CLAUDE.md、无 `paths` 的 rules | 从磁盘重新注入 |
| Auto memory | 从磁盘重新注入 |
| plan 模式写的计划 | 从磁盘重新注入 |
| 带 `paths:` 的 rules、子目录 CLAUDE.md | **不重新注入**，等下次读到匹配文件 |
| 读过/改过的文件 | 重读最近改过的 **5 个**；>5000 token 的只给路径引用 |
| 用过的 skill 正文 | 重新注入，单个 ≤5000 token、总共 ≤25000，**最老的先丢**；截断保留开头 |
| 后台命令/子代理 | 继续跑，并提醒 Claude 哪些还在跑，免得重复启动 |

还有两条工程细节：

- `/compact 带焦点`（`/compact focus on the auth bug`），CLAUDE.md 里可以写一段
  **Compact Instructions** 影响自动压缩保留什么
- **防抖**：单个文件大到压完立刻又满时，压几次就报错，不无限循环

## 2. 哪些抄，哪些不抄

这个产品和 Claude Code 形状不一样，照搬会搬错：

| | Claude Code | AI 短视频工厂 |
|---|---|---|
| 一次会话 | 一个长对话 + 无限工具循环 | **一串短的、结构化的一次性调用** |
| 上下文来源 | 对话历史 + 文件内容 | **从项目状态重建** |
| 「文件」是什么 | 代码 | 项目内容（大纲、剧本、分镜） |

### 2.1 抄

| 抄什么 | 为什么 |
|---|---|
| **两层作用域，拼接不覆盖** | 「我不要旁白」是跨项目的，「这片子的调性」是这个项目的。两件事 |
| **索引每次带，细节按需读** | 索引是常驻成本，所以要有上限；topic 可以写长，因为按需 |
| **索引有上限，超了如实报** | 静默丢掉比报错糟得多 —— 人会以为记住了 |
| **明确跳过能从项目文件推出来的** | 「第二幕有三场」在 outline.md 里。记了只会过期，而过期的记忆比没有更糟 |
| **`modified` 时间戳** | 半年前记的「主角叫李明」和上周记的不是一回事 |
| **两级压缩的思路** | 先扔能从别处重建的，再动真正的内容 |
| **frontmatter + Markdown 的文件形状** | 与 skill 同一套约定（`md::split_front` + `serde_yaml_ng`），人能直接改 |

### 2.2 不抄

| 不抄什么 | 为什么 |
|---|---|
| `paths:` glob 限定 | 这儿的「文件」是项目内容不是代码，按 glob 挂规则挂不到东西上。**对应物是按任务挂**（见 3.3） |
| 目录层级递归查找 | 项目是工作空间下平铺的一个目录，没有 monorepo 那种嵌套 |
| `@import` | 项目内容已经是分文件的；再加一层导入只是多一个会指错的路径 |
| 组织级策略文件 | 这是单机创作工具，没有 IT 统一下发的场景 |
| 把记忆放机器本地 | Claude Code 的 auto memory 不跨机器。但这个产品的**项目是要跟着工作空间走的** —— 记忆放本地会出现「拷到另一台机器，片子的设定没了」 |

最后一条是**刻意与 Claude Code 相反**的选择，理由见 3.1。

## 3. 方案

### 3.1 文件布局

```
<workspace>/
├── MEMORY.md                    ① 我的偏好，跨项目
├── memory/
│   ├── taste-dialogue.md            topic：台词的口味
│   └── taste-visual.md
└── projects/<id>/
    ├── MEMORY.md                ② 这片子要记住的事
    └── memory/
        ├── world-why-silent.md      topic：为什么主角不说话
        └── feedback-outline.md      topic：用户改过我的大纲
```

**两层都在工作空间里，跟着项目走。** 这一条与 Claude Code 不同（它的 auto memory
是机器本地的）。理由：那边的记忆是「Claude 对这个 repo 的了解」，代码本身在版本库
里，记忆丢了还能重建；这边的记忆是**创作决定**（为什么主角不说话、哪个词是禁忌），
丢了就是丢了，而且它跟项目的关系比跟机器的关系紧得多。

代价照旧写清楚：工作空间放进网盘目录的话，记忆跟着进网盘。和 api key 那个取舍
是同一件事，已经定了。

### 3.2 文件格式

索引 `MEMORY.md` —— 人写的，一条一行：

```markdown
# 这片子要记住的事

- 调性是冷的。不要煽情，不要配乐提示
- 主角李明不说话，原因见 `memory/world-why-silent.md`
- 用户连着丢掉三版三幕结构，倾向两幕 —— 见 `memory/feedback-outline.md`
```

topic 文件 —— frontmatter 与 skill 同一套（`md::split_front` + `serde_yaml_ng`）：

```markdown
---
kind: world
summary: 为什么主角不说话
topics: [script.draft, shots.generate]
modified: 2026-09-18T07:30:00Z
---

李明在第一幕中段之后不再开口。这不是性格设定，是他知道说了没用 ——
所以**不要给他加台词**，哪怕一场里只有他一个人。

他的表达全在手上：修表、数硬币、把东西放回原位。
```

字段：

| 字段 | 说明 |
|---|---|
| `kind` | `taste` / `feedback` / `world` / `ref`。见 3.4 |
| `summary` | 索引上那一行说什么。必填 |
| `topics` | 哪几步用得上（任务 id）。**空 = 每步都用得上** |
| `modified` | 自动盖，ISO 8601 |

### 3.3 `topics` 是 `paths:` 的对应物

Claude Code 用 glob 匹配代码文件；这儿用**任务 id** 匹配链路：

```
topics: [script.draft]              只有写剧本时把这条正文拼进去
topics: [shots.generate, shots.prompt]
（不写）                             每条链路都拼
```

这样「这片子的台词口味」不会在拆镜头时占上下文，而「调性是冷的」每步都带。

### 3.4 四类 `kind`

照 Claude Code 那四类换成这个产品的说法。**分类不是装饰，它决定这条该不该记**：

| kind | 记什么 | 作用域 | 反例（不该记） |
|---|---|---|---|
| `taste` | 用户的口味：不要旁白、台词要短、别用「仿佛」 | 多数在工作空间层 | — |
| `feedback` | 用户改过我的东西。连着丢三版是信号 | 项目层 | 「他改了一个错别字」 |
| `world` | 这片子的设定，**推不出来的那些**：为什么主角不说话、哪个词是禁忌 | 项目层 | 「第二幕有三场」——在 outline.md 里 |
| `ref` | 外部参考：某部片子的风格、某个真实事件 | 都可能 | — |

**没有「结构」「进度」这两类**，因为那些能从项目文件推出来。这条要写进提示词，
不然模型会去记「现在有 5 个镜头」这种下一秒就过期的东西。

### 3.5 怎么进模型

在 `run::preamble_of` 里多拼一段，顺序**工作空间在前、项目在后**：

```
人格提示词
  ↓
【记住的事】
  ## 我的偏好（跨项目）
  <workspace MEMORY.md 索引全文>
  ### <命中的 topic summary>
  <正文>
  ## 这个项目要记住的事
  <project MEMORY.md 索引全文>
  ### <命中的 topic summary>
  <正文>
  ↓
skill 清单（第 1 级）
  ↓
这一轮展开的 skill 正文（第 2 级）
```

**索引永远全带**（所以有上限），**topic 正文按 `topics` 命中才带**（所以能写长）。

### 3.6 上限与超限

| 对象 | 上限 | 超了怎么办 |
|---|---|---|
| 索引 `MEMORY.md` | 200 行 / 25 KB（照 Claude Code） | **写入成功，但把实话返回给调用方**：「超出的部分下次不会被加载，往 memory/ 里挪」。界面上显眼地摆出来 |
| 单个 topic 正文 | 8 KB | 截断，**保留开头**（照 Claude Code 注入 skill 的做法：重要的写在前面） |
| 一个作用域的 topic 数 | 不限 | 不限是因为它们不常驻；真多了索引会先撞上限 |

**不静默截断索引** —— 这是抄来的最重要的一条。截了人看不出哪儿被砍，
而下次加载真的会丢。

## 4. 上下文预算（压缩的对应物）

这个产品目前**没有会跑爆的对话上下文**（每次调用都是一次性的）。真正会爆的是
「往输入里塞了多少项目内容」。现在已经有一处粗暴的处理：提取资产送正文时
`slice(0, 8000)` —— 那就是个没写清规则的压缩。

照 Claude Code「先清能重建的，再动真内容」的思路，把它规范化成一份预算表：

| 链路 | 现在送什么 | 预算内的取舍顺序 |
|---|---|---|
| 起草大纲 | 项目名 + 已有幕/场数 | 本来就小，不动 |
| 写剧本 | 本场 + 前一场结尾 + 定稿资产 | ① 前一场结尾缩到 6 行 ② 资产只留本场引用到的 |
| 提取资产 | 全本正文截 8000 字 | ① 按场次**从前往后**送（资产在前几场就出全了）② 超预算截在场次边界，不切在句子中间 |
| 拆镜头 | 要拆的几场正文 + 定稿资产 | ① 一次最多 3 场（现在不限，10 场会撑爆）② 超了分批，界面上如实说「这轮拆了 3 场，还有 7 场」 |
| 补提示词 | 每镜的引用 + 画风 | 按镜分批，已有分批机制 |

两条通用规则：

1. **先扔能从别处重建的**。资产描述扔了可以再查，本场正文扔了这一轮就废了
2. **截断要截在结构边界上**（场次、段落），不截在句子中间。截在句子中间的输入
   会让模型补一个它自己编的结尾

这份表落成代码是 `domain/agent/budget.ts` 一组纯函数（可单测），而不是散在各条
链路里的 `slice(0, N)`。

### 4.1 对话历史：先不做，但要划边界

「再短一点」这类追问要靠对话历史。**这份方案不做它**，理由是它和记忆是两个问题，
混在一起会让两个都做不好：

- 记忆是**跨会话的、人能看能改的、有意保留的**
- 对话历史是**一轮之内的、临时的、会跑偏的**

真要做的时候，做法是：`structured::extract` 多收一个 `history: &[(Role, String)]`，
只送「人说的话 + 模型的 reply」，**不送步骤卡与产物预览**（那些是界面结构，
进上下文只是噪音），并且封顶最近 3 轮。

这一条单独记成 task，不放进这次。

## 5. 谁来写记忆

两条路都要，但优先级不同。

### 5.1 人写（先做）

这是 Claude Code 的 CLAUDE.md 模型：**人写的那份是主的**。对应界面：

- 项目里多一个「项目备忘」入口，直接编辑 `<project>/MEMORY.md`
- 设置里多一个「我的偏好」，编辑 `<workspace>/MEMORY.md`
- 两处都在编辑器下面如实显示「索引 X 行 / 上限 200 行」，超了变警示色

`/init` 的对应物：项目有了大纲和剧本之后，给一个「帮我起个草」——
读一遍项目内容，提议几条备忘，人改完再存。**提议不直接落盘**。

### 5.2 模型自己记（后做，而且要改触发点）

Claude Code 的 auto memory 挂在**对话纠正**上（「你说错了，应该用 pnpm」）。
这个产品没有那种长对话，所以那个触发点搬过来是空的。

对应的信号在**采纳/丢弃**上：

| 信号 | 可能该记什么 |
|---|---|
| 连着丢掉同一类产物 ≥3 次 | `feedback`：用户不要这个形状 |
| 采纳后手改了正文 | `feedback`：把改动的方向记下来 |
| 用户在输入里反复说同一个约束 | `taste`：这不是一次性要求 |

这条的**风险要说清**：自动记错了比不记糟。所以：

- 每条都要人确认才落盘（界面上一句「要把这条记下来吗」），**不静默写**
- 只记 `feedback` 和 `taste` 两类；`world` 和 `ref` 只能人写 ——
  设定被猜错了会一路错下去
- 记之前查一遍索引，已经说过的不重复记（照 Claude Code 那条）

## 6. 实现分段

每段都是能独立验证、能单独提交的：

| 段 | 内容 | 落在哪儿 | 验证点 |
|---|---|---|---|
| **A** | `memory` 模块：读写、frontmatter、上限判定、`modified`、`compose()` | `src-tauri/doc/src/memory.rs`（`doc` 已有 `md::split_front`、`store::write_text`） | 纯函数全测：两层拼接顺序、`topics` 命中/不命中、索引超限返回实话而不是截断、topic 超长截在字符边界、条目名不能带路径 |
| **B** | 拼进 preamble | `agent/src/run.rs` 的 `preamble_of` + `skill::compose_preamble` | 记忆在人格之后、skill 正文之前；没有记忆时一个字都不多（现有测试同款断言） |
| **C** | IPC + 界面 | `app/src/lib.rs` 三条命令（读/写索引/写 topic）、项目页与设置页两个编辑器 | 超限时界面真的变色并说清怎么办；反向验证去掉那段警示会挂 |
| **D** | 上下文预算 | `src/domain/agent/budget.ts` 纯函数 + 各链路改用它 | 截断截在场次边界；超预算时界面如实说「这轮只送了 3 场」 |
| **E** | 模型自己记 | 丢弃/手改的信号 → 提议 → 人确认 | 提议不落盘；已经在索引里的不重复提议 |

建议顺序 **A → B → C**，到这儿「人写的记忆真的会进模型」已经成立，是一个完整可用
